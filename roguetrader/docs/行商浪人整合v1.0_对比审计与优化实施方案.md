# 《行商浪人整合 v1.0》对比审计与优化实施方案

审计日期：2026-08-20
对比对象：`行商浪人整合v1.0.chm`、`魔王之影大全5_6_2.chm`
首轮整改产物：`行商浪人整合v1.1.chm`

## 一、结论

《行商浪人整合 v1.0》的内容保存、统一样式、图片完整性和 CHM 链接可靠性总体不错，主要短板不在“有没有内容”，而在“内容能不能快速定位”。它目前更像 20 份来源文件的网页化合集；范例《魔王之影大全》的核心优势，则是把内容拆成大量独立主题，并使用较深的树形目录组织。

最值得借鉴的是范例的信息架构，而不是其 HTML 写法。范例本身存在 16 个目录失效目标、973 页异常字符集声明、若干本机临时图片路径和大量 Word/WPS 冗余标签，不能直接照抄。

首轮应优先处理核心规则书，原因如下：

1. 核心书是最高频入口，但 v1.0 的侧栏只显示 15 个章标题，原书已有的 164 个小标题没有暴露。
2. 核心书被机械切成 60 卷，卷名只有“分卷 x/60”，无法说明当前内容。
3. DOCX 转换保留了大量表格占位列，导致有效内容被压窄、中文逐字换行。
4. 原书目录、正文锚点和 Word 缩进均完整，不必依赖模型猜测，可确定性恢复层级。

## 二、审计方法与统计口径

- 以两个已发布 CHM 本体为准重新解包，不以源工程代替最终产物。
- 扫描 HTML/HTM、HHC 目录、HHK 索引、CSS、图片、内部链接和锚点。
- 用 1280×900 浏览器窗口抽样渲染首页、正文、长表格、更新日志和规则主题页。
- “断链”分为文件不存在和页内锚点不存在；HHC/HHK 另行验证。
- 下表为整改前 v1.0 与范例的统计数据。

## 四、范例值得借鉴的地方

### 1. 一个规则主题对应一个页面

范例将种族、道途、法术、地区、冒险等拆成独立页面。用户从目录点击后直接抵达目标，不需要先进入大文件再滚动查找。

可用于行商浪人的做法：

- 最高频规则按“章 → 节 → 小节”暴露到侧栏。
- 对武器、天赋、技能、星舰组件等高频查询对象，后续可进一步生成独立主题页或字母索引页。
- 页面标题使用真实规则名，避免仅显示“分卷 37/60”。

### 2. 深层树形目录

范例 HHC 最深达到 8 层，能表达“资料集 → 书 → 章 → 主题 → 子主题”的归属关系。行商 v1.0 最大深度只有 2，核心书 180 个原始目录锚点中仅显示 15 章。

适合行商浪人的目标深度是 3–4 层，不必机械追求 8 层：

```text
行商浪人核心规则书
└─ 第九章：进行游戏
   ├─ 检定
   │  ├─ 对抗检定
   │  └─ 检定难度
   ├─ 协助
   └─ 战斗
```

### 3. 页面短、入口明确

范例页面文本中位数约 810 字，行商约 8,814 字。短页面更适合 CHM 的左栏定位和窗口阅读。

但不建议立即把核心书拆成 180 个物理页面。第一阶段保留 60 个安全分卷，通过树形锚点和“本卷内容”解决定位；第二阶段再按章节边界进行语义分卷，避免破坏复杂表格。

## 五、行商浪人需要优化的地方

### P0：核心规则书导航与表格

问题：核心书只有章级侧栏；60 个机械分卷缺少语义；表格空列导致有效列过窄。

具体调整：

1. 从 DOCX 前几页目录读取全部 180 个 `HYPERLINK \l "bookmark…"` 字段。
2. 使用 Word 段落缩进恢复层级，而不是用标题文字猜测：
   - 缩进约 93：书名节点，不在子目录重复显示；
   - 缩进约 513：章；
   - 缩进约 931–951：节；
   - 缩进约 1038–1049：三级小节。
3. 将目录页码尾缀从显示名称移除，但保留原锚点目标。
4. 每个分卷顶部加入“本卷内容”，列出该卷实际包含的小标题。
5. 前后卷导航增加“卷首目录”，并改用 IE9 兼容的浮动布局。
6. 删除整列为空的 Word 占位列；仅有一个有效单元格的行合并为跨列表头；删除纯空白行。
7. 保留有效列的原始比例，避免中文短字段被挤成逐字竖排。

验收标准：

- 核心书侧栏包含 15 章、158 节、6 个三级小节。
- HHC 最大深度由 2 提升到 4。
- HHC 文件目标和锚点失效均为 0。
- 随机抽查姓名表、武器表、技能表、星舰表，不出现由空白占位列造成的大面积留白。

### P1：修复正文内部链接

问题：v1.0 有 91 个正文页内失效锚点，其中：

- `RT灵魂掠夺者` 对应页面 63 个；
- `译文：舰船职务` 对应页面 28 个。

具体调整：

1. 在 DOCX 转 HTML 后统一执行 `add_heading_ids`。
2. 建立“原 href → 清洗后标题 → 新 id”的映射。
3. 对中文标点、空格、全角符号、序号进行规范化后再匹配。
4. 一对多或低置信度目标交给 DeepSeek 输出候选 JSON，但必须由相似度和唯一性规则复核。
5. 构建失败条件：任何新生成的内部 href 找不到文件或锚点时中止发布。

### P1：让 HHK 成为真正的关键词索引

问题：行商 v1.0 的 1,404 个 HHK 条目几乎是目录的平铺副本，数量多但不利于按概念检索。

具体调整：

- 为高频概念添加别名：例如“PF/利润因子”“舰船点/SP”“导航者/领航员”等。
- 对技能、天赋、武器、护甲、星舰组件生成独立关键词。
- 同名条目保留多目标，但名称增加来源限定，例如“武器（核心书）”“武器（灵魂掠夺者）”。
- HHK 保持扁平字母/汉字索引；HHC 负责层级，不再让两者完全重复。

### P1：按语义重新分卷

问题：当前按每 10 个顶层 DOCX 块切分，能保护表格但不能保证语义完整。

可执行策略：

1. 先以章锚点为硬边界。
2. 章过大时，再以目录中的二级标题为候选边界。
3. 表格、图片及其标题作为不可拆分块。
4. 单页目标建议 20–80 KB；超过 150 KB 再拆分。
5. 文件名保持稳定 ID，显示标题改为“第九章：进行游戏（二）”等语义名称。

### P2：OCR 与文本质量

问题：钛帝国手册可见明显 OCR 错误，例如标题字母误识别、英文单词缺字、中文断裂。首页目前直接标记为“PDF OCR + DeepSeek”，但没有告诉用户哪些页经过人工复核。

具体调整：

- 为每份来源记录 `source_type`、`ocr_engine`、`ai_reviewed`、`human_reviewed`。
- DeepSeek 仅做段落修复候选，不直接覆盖原文；保存原 OCR 和修订 diff。
- 专有名词使用项目词表锁定，禁止模型自由改写数值、骰式、规则关键字。
- 对数字、骰式、表头进行正则校验，例如 `d10`、`1d5`、百分数、距离单位。
- 页面顶部显示质量标签：“人工校对”“AI 初校”“原始 OCR，慎用”。

### P2：图片、体积和替代文本

问题：图片约占 v1.0 总体积的 90%，136 张图片没有 `alt`。

具体调整：

- 照片/扫描图转 JPEG，质量 82–88；线稿和透明图保留 PNG。
- 对超出正文显示尺寸两倍以上的图片降采样。
- 用 SHA-256 去重跨文档重复图片。
- 装饰图使用空 `alt`，规则图使用“来源 + 页码 + 图名”。
- 构建报告列出单张超过 500 KB 的图片和总体积变化。

### P2：搜索体验

具体调整：

- 搜索结果跳到最相关的小标题锚点，而不是只打开所属分卷顶部。
- 标题命中、关键词命中、正文命中分别赋权。
- 支持中英文别名、全半角归一和常见译名。
- 搜索片段高亮所有查询词，并显示来源书名与章节路径。
- 保留 CHM 原生全文索引，同时保留自定义搜索页作为兼容入口。

### P3：构建质量门槛

每次发布前自动生成并检查：

- HHC/HHK 条目数、最大深度、重复名称、缺失目标、失效锚点；
- HTML 标题重复、重复 id、内部链接、图片路径；
- 每页字符数、表格空单元格比例、超大图片；
- 原生全文索引 `/$FIftiMain` 是否存在；
- 输出文件大小和 SHA-256；
- 首页、核心书目录、至少四类表格的截图回归。

## 八、第二阶段实施规范：取消分卷，改为语义小节页

第二阶段不再保留“分卷 1/60”一类机械分页。核心规则书应重建为“一个侧栏语义节点对应一个 HTML 主题页”。

### 8.1 页面与侧栏的对应关系

- 点击章节点时，只显示该章标题之后、首个子节之前的章级导言。
- 章节点没有独立导言时，显示本章小目录，不复制所有子节正文。
- 点击节节点时，只显示从当前节锚点开始、到目录顺序中的下一个节点之前的内容；若下一节点是其三级子节，也在子节开始前结束。
- 点击三级小节时，只显示该三级小节自身内容，不重复父节或相邻小节。
- 封面、译者信息和重新生成的目录保留在核心书首页。
- 原来的 60 个分卷文件不再出现在侧栏、索引或搜索结果中。
- 页面保留“上一节、返回上级、下一节”导航，顺序依据原书目录，而不是旧分卷编号。

### 8.2 稳定文件名与兼容策略

语义页面使用原始书签作为稳定 ID，例如：

```text
core-bookmark77.html   第九章：进行游戏
core-bookmark78.html   检定
core-bookmark79.html   对抗检定
```

- 显示名称可以在以后校订，但文件地址不随译名、空格或标点变化。
- 正文交叉引用、HHC、HHK 和全文搜索必须统一迁移到新地址。
- 如旧分卷 URL 存在外部使用场景，可生成不出现在侧栏中的兼容跳转页；默认新版本不再暴露旧分卷。

### 8.3 内容边界规则

切分以原 DOCX 目录字段、正文书签和 Word 块边界为准，不按字符数或固定块数切分。

1. 当前节点内容从其书签所在块开始。
2. 到目录顺序中的下一个节点所在块之前结束，不让父节点吞并紧随其后的子节点正文。
3. 父节点页面不吞并子节点正文。
4. 标题书签落在复杂表格内时，完整表格作为不可拆分块归入对应小节。
5. 图片、图片标题、表格标题与其后对象保持为同一个不可拆分内容组。
6. 没有正文的目录节点生成小目录页，不生成真正的空白页。
7. 原目录页只作为层级数据来源，展示时改为重新生成的干净 HTML 目录。

### 8.4 文字排版规范

- 正文字号由 15px 提高到约 16px，行高调整为约 1.75–1.8。
- 正文区域保持舒适行宽；超宽窗口下不让段落无限延伸。
- 章、节、三级小节使用统一而明确的标题层级。
- 普通叙述、属性条目、规则定义、引用、示例和说明框分别使用适合的版式。
- 清理无意义空段落、多层 `blockquote`、固定英寸尺寸及冗余行内样式。
- 不对所有段落机械添加首行缩进；连续叙述可缩进，规则条目和短标签不缩进。
- 不改写规则含义、数值、骰式、距离、专有名词和表格数据。

### 8.5 页面边框与表格处理规范

核心书中的表格需要区分两类：

- 布局表格：Word 用来模拟页面、分栏、文本框或页面边框的表格。应拆成普通段落和容器，不保留边框。
- 数据表格：武器表、技能表、随机表、属性表等真实规则数据。应保留并重新整理。

具体要求：

1. 移除包围整页或整段正文的外层单格表格及页面边框。
2. 递归解除仅用于布局的嵌套表格，不丢失其文本、图片和书签。
3. 删除数据表中的全空列、全空行和纯占位单元格。
4. 单内容标题行合并为跨列表头。
5. 优先识别并使用 `<thead>`、`<th>`、合理的 `colspan` 和列宽。
6. 保留有效列的相对宽度，防止中文短字段逐字竖排。
7. 宽表格放入兼容 CHM/MSHTML 的横向滚动容器。
8. 表格不得在语义页面边界处被切成两个无效片段。

### 8.6 搜索、索引与交叉链接

- 每个语义小节作为一个独立搜索文档。
- 搜索结果直接进入目标小节页，不再进入旧分卷顶部。
- HHC 保留“书 → 章 → 节 → 三级小节”结构。
- HHK 使用相同稳定目标，并逐步补充中英文别名和术语别名。
- 所有原 `topic001-partNNN.html#bookmark…` 链接改写为 `core-bookmarkNNN.html`。
- 发布门槛为：新核心页面、HHC、HHK、正文交叉引用均无缺失文件和失效锚点。

### 8.7 DeepSeek 使用边界

DeepSeek 可以用于：

- 目录文字与正文标题不一致时提供候选匹配；
- 判断疑似标题、表格标题、说明框和断裂段落；
- 为不规则表格提出结构化候选；
- 识别重复标题的语义区别。

DeepSeek 不得直接自由改写规则正文。模型输出必须为可复核的结构化候选；数值、骰式、规则关键词和专有名词仍由确定性校验保护。

### 8.8 第二阶段验收标准

- 核心书不再出现“分卷 x/60”文件或文案。
- 每个侧栏末级节点只包含当前节点的正文。
